# FilaSeg — Filament Quantification Pipeline

This document walks through the FilaSeg pipeline end-to-end, stage by stage, with figures and an animated progression.

The example outputs in the figures below come from `stringart_tiles.py`, the pipeline's only
stage-1 path:

```powershell
python Tools\run_full_sem_pipeline.py `
  --mask input\sem_full_00000_1p66_crop512\mask.png `
  --background input\sem_full_00000_1p66_crop512\sem.png
```

An experimental skeleton-first stage-1 alternative was built, tuned, and benchmarked at length
but never beat tiled Hough; it was removed 2026-07-14. See
[`../Experimentation.md`](../Experimentation.md) for the full comparison.

All figures live in [`figures/`](figures/) and can be regenerated by running:

```powershell
python docs\generate_figures.py
```

## 1. End-to-end overview

The pipeline turns a binary filament mask (and an aligned SEM image) into per-filament instance labels and a DEM-ready JSON.

![End-to-end pipeline block diagram](figures/01_block_diagram.png)

Inputs and outputs at each boundary:

| Stage | Input | Output | Script |
|---|---|---|---|
| 1. stringart | `mask.png` | per-angle branches `mask_branch_*.png`, `reconstructed.png`, `run_config.json` | [`1.stringart/stringart_tiles.py`](../1.stringart/stringart_tiles.py) |
| 2. preprocess | per-angle branches | cleaned per-angle branches | [`2.preprocess/preprocess_stringart_branches.py`](../2.preprocess/preprocess_stringart_branches.py) |
| 3. reconnect | cleaned per-angle branches | layered multilabel TIF, labels TIF, rejection log CSV | [`3.reconnect/reconnect_run.py`](../3.reconnect/reconnect_run.py) |
| 4. postprocess | layered multilabel | smart-width rendered labels, color preview, overlay, summary | [`4.postprocess/post_process_reconnect.py`](../4.postprocess/post_process_reconnect.py) |
| handoff | postprocess outputs | `final/` folder + DEM JSON | [`Tools/run_full_sem_pipeline.py`](../Tools/run_full_sem_pipeline.py) |

The end-to-end runner is:

```powershell
python Tools\run_full_sem_pipeline.py `
  --mask input\sem_full_00000_1p66_crop512\mask.png `
  --background input\sem_full_00000_1p66_crop512\sem.png
```

## 3. Stage 1 — stringart (orientation decomposition)

**Input**: binary mask.
**Output**: 12 per-angle branch images (15° wide bins by default), a `reconstructed.png` (union of all branches), and a `run_config.json` recording every CONFIG knob and a stats block.

This is `1.stringart/stringart_tiles.py`, the pipeline's only stage-1 method. It is a tiled Hough vectorizer with multi-grid voting:

1. Tile the mask into overlapping cells (`--tile-size`).
2. Within each tile, find candidate line segments with probabilistic Hough.
3. Accept a candidate only if both gates pass:
   - **New residual pixels**: the candidate must add at least `--min-accept-newpix` previously-unclaimed mask pixels.
   - **Support density**: at least `--min-accept-density` fraction of the candidate's pixels must lie on the original mask (rejects long fake chords over background).
4. Optional **multi-grid voting**: run the above at `--tile-grid-offsets` shifted grid origins and keep only pixels appearing in `--tile-grid-vote-min` of them.
5. Assign every accepted segment to one of the 12 angle bins from its slope; the bin's image is built up over the run.

![Stage 1 mask → branches](figures/02_stage1_branches.png)

The colored middle panel shows each branch's pixels as one color from a 12-color hsv palette; the right panel is the union (reconstructed). Coverage of the original mask is high (typical ≥ 95%).

## 4. Stage 2 — preprocess (per-branch cleanup)

**Input**: raw per-angle branches from stage 1.
**Output**: cleaned per-angle branches (same filenames, prepared for reconnect tip-tip scoring).

For each branch:

1. Threshold to binary.
2. Drop connected components below `--pre-min-component`.
3. Apply an oriented morphological close along the branch's angle (`--pre-line-close-len`, `--pre-line-close-iters`) to bridge tiny raster gaps along the bundle direction.
4. Optionally reduce each component to its dominant two-tip skeleton path (`--pre-clean-to-path`, `--pre-clean-smooth-win`).
5. Fit a parametric B-spline (`--pre-fit-degree`, `--pre-fit-smoothing`) to enforce a physically reasonable curve.

![Stage 2 cleanup](figures/03_stage2_clean.png)

The left column shows one branch (and the union of all branches) before preprocess; the right column after. Specks are gone, gaps are bridged, and components are smoothed.

## 5. Stage 3 — reconnect (staged tip merging)

**Input**: cleaned per-angle branches.
**Output**: multilabel TIF (one page per ID), flat labels TIF, overlap PNG, optional rejection-log CSV.

Each cleaned component becomes one Component. Reconnect then runs three ordered tip-merge stages over the Components, each one broadening the geometric gates:

| Stage | Role | Typical gates |
|---|---|---|
| `stage_clear` | tiny, very-collinear endpoint gaps only | dist ≤ 16, opp ≥ 0.6, residual ≤ 6 |
| `stage_strict` | short-gap reconnect with all gates active | dist ≤ 15, fwd ≥ 0.85, opp ≥ 0.55, residual ≤ 6 |
| `stage_relaxed` | wider-gap reconnect with relaxed gates | dist ≤ 50, fwd ≥ 0.72, opp ≥ 0.4, residual ≤ 16 |

Same-layer relaxation (`same_layer_*`) allows two Components in the same orientation bin to merge through a higher residual than the global gate would allow. Overlap handling is configurable (`overlap.mode`: `trim` or `kill`, with `kill_thr` and optional `trim_dilate_px`). After the staged passes a few "smooth" sweeps iteratively re-evaluate alive Components.

![Stage 3 reconnect](figures/04_stage3_reconnect.png)

Left: cleaned preprocess fragments overlaid on the SEM. Right: reconnected bundles, one color per ID. The number of distinct colors equals the multilabel page count.

### 5.1 What the gates actually look at

Every candidate merge is scored on four geometric measurements computed from the **skeleton endpoints (tips)** of two Component fragments:

- **dist** — Euclidean distance between the two tips.
- **forward cosine** — alignment of each tip's *outward* tangent with the line connecting them. High forward cosine means each tip is "looking at" the other.
- **opposition** — dot product of the inward tangents at the two tips. ≈ +1 when the two fragments are co-linear and would form a smooth continuation.
- **line residual** — how far the midpoint of the gap is from each tip's tangent line, averaged. Low residual means both tangents extrapolate through the gap.

![Reconnect gate schematic](figures/09_reconnect_gates.png)

Each stage has a different threshold cocktail:

| Stage | dist | forward cos | opposition | residual | when it fires |
|---|---|---|---|---|---|
| `stage_clear` | ≤ 16 | — | ≥ 0.6 | ≤ 6 | tiny, highly-collinear gaps; the cheapest "obvious" merges |
| `stage_strict` | ≤ 15 | ≥ 0.85 | ≥ 0.55 | ≤ 6 | short gaps with the full geometric posture |
| `stage_relaxed` | ≤ 50 | ≥ 0.72 | ≥ 0.4 | ≤ 16 | wider gaps where alignment is good but distance is borderline |

A T-junction (one filament ending against the side of another) typically has tip-tip distance close to zero **but** opposition near 0 (the tangents are perpendicular), so all three stages reject it — exactly the desired behavior.

Setting `debug.rejection_log_path` in `reconnect_config.yaml` writes per-candidate metrics (stage, base/target IDs, tip coords, gates, reasons) to a CSV that the troubleshooting CLI can interrogate.

## 6. Stage 4 — postprocess (smart-width rendering)

**Input**: reconnect multilabel.
**Output**: final labels TIF, color preview, overlay PNG, post-process summary.

For each reconnect layer:

1. Skeletonize the layer's binary mask.
2. Extract the dominant endpoint-to-endpoint path.
3. Smooth the path with a moving window (`--smooth-window`).
4. Estimate one rendered width per ID using **smart-width**: sample opposite-slope SEM edges normal to the path; use the median sample (with outlier trim). If edge evidence is weak, fall back to `--thicken-px`.
5. Render the smoothed path at that width.
6. **Overlap absorb** (`--overlap-absorb-thr`): pairs whose intersection covers ≥ thr of the smaller mask are merged into the larger.
7. **Occlusion trim** (`--occlusion-trim-thr`, `--occlusion-trim-min-px`): trim lower-priority layers that are mostly already covered by earlier ones.
8. Flatten layered output with first-write-wins priority (longest skeleton first).

![Stage 4 final](figures/05_stage4_postprocess.png)

Left: stage 3's thin reconnect IDs. Right: stage 4's smart-width final bundles. Each filament is now rendered at its measured physical width instead of a fixed thicken radius.

## 7. Troubleshooting handles

The most useful entry points when investigating a missed/incorrect merge:

```powershell
# Compare two runs on a curated pair list
python Tools\troubleshoot_reconnect.py compare-followups --old-run <a> --new-run <b> --pairs 31,14 13,43

# Explain which reconnect gates fired/failed for a pair
python Tools\troubleshoot_reconnect.py diagnose-missed --run <name> --pairs 17,29 10,56

# Check whether two visual coordinates share a final ID
python Tools\troubleshoot_reconnect.py check-coords --run <name> --coords "pairA|120,240|130,248"

# Trace one run's IDs back through reconnect, preprocess, stringart
python Tools\troubleshoot_reconnect.py trace-component --run <name> --step final --ids 25 38 42

# Render side-by-side SEM crops for a list of pair IDs
python Tools\troubleshoot_reconnect.py visualize-pairs --run <name> --pairs 22,20 27,59
```

A typical investigation path for a "should-have-merged" pair:

1. `diagnose-missed` to see which gate(s) rejected the candidate, with `dist`, `forward_*`, `opposition`, `line_resid`.
2. `trace-component` on each ID to see which preprocess/stringart branches contributed.
3. If the tips are physically close but reconnect's tangents disagree, the split is usually a stage-1 fragmentation problem.
4. If the geometry truly fails, tighten/loosen the relevant gate in `3.reconnect/reconnect_config.yaml`.

## 8. Output handoff

The end-to-end runner copies post-process outputs into a single `final/` folder so downstream tooling has one place to look:

```text
output/full_pipeline/<base>/final/
  <base>_reconnect_labels.tif         integer label image (one bundle per ID)
  <base>_instances_color.png          colored bundle preview
  <base>_reconnect_overlay.png        overlay on SEM
  <base>_original.png                 background copy
  <base>_reconnect_multilabel.npz     sparse per-ID indices
  <base>_reconnect_multilabel.tif     one TIFF page per ID
  <base>_bundles_dem.json             DEM-ready geometry export
  <base>_pipeline_manifest.json       paths + parameters + interactive command
```

The DEM JSON uses schema `filaseg.dem_bundles.v1`. Coordinates are pixels, origin at top-left. Each bundle includes id, area, bbox, centroid, estimated length, mean width, endpoints, and centerline in both `rc` (row, col) and `xy` (x=col, y=row) form.
