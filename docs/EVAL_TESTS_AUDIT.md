# Audit of `eval/` and `tests/`

Date: 2026-07-29. Scope: every `.py` and `.md` file directly in `eval/`, every file in
`tests/`, and the three result subfolders under `eval/`.

## Topology at the time of the audit

`eval/`, `tests/` and `docs/` were **entirely untracked** — no per-file git history existed
to cross-check against, so "last touched" evidence below is filesystem mtime plus
cross-reference, not commit lineage. `paper/` and `sandbox/` were also untracked, and are
now explicitly ignored (see `.gitignore`). This audit is the commit that first brings
`eval/` and `tests/` under version control.

## Headline conclusions

1. **No file was found to be a genuine duplicate or an outright superseded reimplementation.**
   The two most plausible candidates were checked directly and both were ruled out — see
   [Duplicate and overlap checks](#duplicate-and-overlap-checks).
2. **Four scripts are stranded on a retired `output/` layout.** `error_table.py`,
   `length_analysis.py`, `quantify_compare.py` and `orient_method.py` all hardcode the same
   four-case `CASES` list pointing at `output/audit/*`, `output/synthetic_val/*` and
   `output/full_pipeline/sem00000_crop512_manual/...`. Verified: none of those paths exist
   in the current `output/` tree (which is now `output/locked_evaluation/`,
   `output/development_*/`, `output/thick_sweeps/`, …). None of the four has a CLI override.
   Consequently the three `eval/*_out/` result folders **cannot be regenerated by re-running
   their owning script today**.
3. **13 of 20 `eval/` modules have no dedicated test.** The 7 that do are exactly the
   locked-paper-pipeline set.
4. **Two modules were promoted into `eval/` from `sandbox/`** as part of this cleanup —
   `synth_thick.py` and `quant_suite.py`. See the sandbox section of `Experimentation.md`.
5. **No deletions were performed.** Section [Deletion candidates](#deletion-candidates-awaiting-review)
   lists what a reviewer should decide on; nothing there has been acted upon.

### Cross-repository coupling (fixed)

`tests/test_result_macros.py` imported `paper/figscripts/make_result_macros.py` at module
scope. Because `paper/` is a local working copy of a *separate* repository and is not
tracked here, a fresh clone of the coding repository could not run its own test suite — the
import raised before any test executed. The import is now guarded and the test class is
`skipIf`-decorated. Verified both ways: 2 tests run when `paper/` is present, 2 skip with
exit code 0 when it is not.

## Duplicate and overlap checks

- **`metrics.py` vs `common_metric.py` — not duplicates.** The split is deliberate and
  documented in `common_metric.py`'s own docstring: `metrics.py`'s fragment set depends on
  FilaSeg's Stage 1/2 internals and therefore shifts whenever those stages change, so it
  cannot fairly score an external baseline that never produces such fragments.
  `common_metric.py` derives fragments from the input mask alone. Neither calls the other's
  internals.
- **`eval_reconnect.py` / `run_batch.py` / `experiment_runner.py` / `real_ablation_runner.py`
  — four distinct roles**, not reimplementations: single-run CLI + selftest; batch-over-samples
  driver; locked paired-scene evaluator; frozen-config real-crop ablation sweep.
- **`synth_generator.py` vs `synth_thick.py` — not a fork.** `synth_thick.py` does
  `import synth_generator as G` and builds on its rendering primitives.
- **`error_table` / `length_analysis` / `quantify_compare` / `orient_method`** share a common
  template (identical `CASES` list, identical `sys.path` insert) but each computes a
  genuinely different statistic. Shared boilerplate, not shared logic.

No file was merged. Per the cleanup brief, merging purely to reduce file count was not done.

reproducibility of the three `*_out/` folders.
