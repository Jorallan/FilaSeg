## Lead scientific decision

The current common-fragment construction is method-independent, but the
published cross-method score is not representation-equivalent. FilaSeg is
loaded from the Stage-4 multilabel result copied into `final/`; connected
components and minimum-turn are scored from thin label maps derived directly
from the input axis mask. Stage 4 also performs rendered-layer absorption,
occlusion trimming and short-piece removal. It can therefore change both the
fragment-to-instance evidence and the instance grouping.

This is an evaluation defect even though its observed direction is conservative
for FilaSeg. The corrected primary comparison must use equivalent, pre-rendering
centreline-instance representations. The old Stage-4 result should remain as a
clearly labelled end-to-end diagnostic, not the primary baseline comparison.

No hybrid or redesigned method may be selected using the existing locked set.

## Evidence

### Representation and Stage-4 effect

`instance_io.find_pred_artifact` searches `final/` before `3.reconnect/` and
prefers overlap-aware NPZ artifacts. The experiment runner passes that artifact
to the common evaluator. Baselines instead pass their in-memory thin label
images. All 125 locked FilaSeg runs retain both Stage-3 and Stage-4 artifacts,
so a read-only paired rescore is possible without rerunning the pipeline.

A read-only rescore with the existing evaluator gave:

| FilaSeg Stage-3 common-fragment F1 | 0.7337 | [0.7170, 0.7508] |
| FilaSeg Stage-4 common-fragment F1 | 0.6807 | [0.6606, 0.7013] |
| Stage 4 minus Stage 3 | -0.0530 | [-0.0605, -0.0450] |
| Stage-3 FilaSeg minus minimum-turn | +0.0704 | [+0.0561, +0.0847] |
| Stage-4 FilaSeg minus minimum-turn | +0.0174 | [+0.0038, +0.0304] |

These are audit calculations, not yet the replacement machine-readable report.
The final corrected numbers must also apply the predeclared singleton-noise and
stratified-bootstrap corrections below, record artifact-stage provenance, and
be generated by tested code.

### Ground-truth-unassigned fragments

`common_metric.pairwise_scores` removes every fragment with ground-truth
assignment zero before constructing the contingency table. The manuscript says
that a fragment unassigned on either side is retained as its own singleton.
Those statements are inconsistent.

The locked set contains 58 ground-truth-unassigned common fragments across 46
of 125 scenes, with at most three in one scene. Excluding them means that
attaching false input evidence to a predicted instance cannot create false
co-clustered pairs. The scientifically preferable correction is to retain each
ground-truth-unassigned fragment as a distinct singleton and apply the same rule
to prediction-unassigned fragments. The legacy conditional score should remain
available and named explicitly for regression and historical comparison.

### Statistical resampling

The manuscript specifies bootstrap resampling within density. The current
overall runner pools all 125 scenes into an ordinary unstratified bootstrap.
The balanced design leaves the overall point mean unchanged, but the interval
procedure does not match the stated design. Corrected aggregate intervals and
paired intervals must resample scenes within each density, with paired methods
using the same sampled scene indices.

### Claimed cross-checks

The Methods section says common-fragment ARI and directional variation of
information are reported alongside pairwise F1. The current common evaluator
does not emit them. ARI, variation of information and panoptic quality in the
existing report occur only inside representation-dependent native diagnostics.
They are not valid cross-method common-fragment cross-checks.

The correction should compute ARI and directional variation of information on
the same singletonized common-fragment partitions. Pixel panoptic quality
should not be presented as representation-equivalent unless every method is
rendered under an identical declared protocol.

### Provenance

The locked report records code and configuration hashes, seeds and paths. The
current manifest does not contain the input, ground-truth and output artifact
hash columns claimed by the manuscript. The corrected derived report and
manifest must record those hashes, the selected artifact stage, representation
transform, software versions, bootstrap seed and source locked-report hash.

## Minimum-turn interpretation

The published Stage-4 difference of +0.017 is statistically resolved under its
current bootstrap but practically small. FilaSeg also has slightly lower
common-fragment object recovery than minimum-turn in that report, so the result
contains a precision-recall and pair-weighting trade-off. Statistical
significance does not establish a practically important general advantage.

The preliminary Stage-3 difference is larger, but it cannot support a revised
claim until the equivalent-representation transform, singleton-noise policy,
stratified uncertainty and exact artifact provenance are implemented and
validated. Any conclusion must remain conditional on the procedural generator,
degraded one-pixel input and locked parameter settings. No claim of general
superiority is supported.

These remain presentation-only only when their numerical sources are unchanged.

### 2. Metric and evaluation corrections

- generate a new, non-overwriting representation-audit report;
- score all methods on equivalent centreline-instance representations;
- report Stage 3, Stage 4 and their paired difference separately;
- retain ground-truth-unassigned fragments as singleton false evidence and
  preserve a named legacy mode;
- add common-fragment ARI and directional variation of information;
- use stratified paired bootstrap intervals for aggregate locked estimates;
- record per-artifact hashes and representation-stage provenance;
- regenerate dependent tables, macros and figures from the corrected report.

These corrections can change reported values and manuscript conclusions. They
must be committed separately from presentation work.

### 3. New experiments

- select three largest FilaSeg wins, three largest minimum-turn wins and two near
  ties automatically from corrected paired F1 differences, then generate
  fixed-layout qualitative panels;
- diagnose the development-only clean-mask result at 30% without treating four
  scenes as confirmatory evidence;
- compare the four requested fragment-source and grouping-rule hybrids on
  development data using one fixed reference fragment set;
- run a factorial synthetic development study that independently controls
  centreline length density and true width distribution, while recording
  achieved thick coverage, one-pixel coverage, crossing density, filament count
  and gap statistics.

Locked scenes may be analysed for evaluation correction and error
characterization, but never used to select a hybrid or redesigned method.

### 4. Method redesign

The hybrid combinations are candidate redesigns, not corrections to the locked
FilaSeg implementation. Their selection must use development-only data and a
predeclared rule. If a changed method is selected, it requires a new,
independently seeded locked evaluation set and must retain a distinct method
name and configuration. It must not replace the 125-scene report.

No qmax or legacy implementation code should be removed during this work.
Any later cleanup requires a separate commit and regression tests proving
identical output with the gate disabled.

### 5. Future work and scope

Length, width, curvature and other exported measurements are not currently
validated against matched per-instance truth across independent real data.
Unless such validation is completed, remove "and quantification" from the title,
keywords and headline claims. The exports may remain documented as unvalidated
pipeline outputs.

Independent real validation across crops, parent images, instruments, materials
and acquisition conditions remains future work. One development crop cannot
support population claims.
